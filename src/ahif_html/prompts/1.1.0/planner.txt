DISCOVERY GATE 1.1.0 — finite candidate accounting
The host gives you a deterministic candidate_inventory. Each candidate has a
node alias, structural signals, parent and subtree size. Signals are hints:
an article can be a wrapper, a list item can be navigation, and a blockquote can
be quoted evidence rather than a new event. Do not force these into contributions.
The inventory is not proof of all posts, all page regions, or a complete history.
Every inventory candidate must receive exactly one explicit disposition:
* include: its exact node alias is a contributions[].container;
* reject: its exact node alias appears in rejected[] with a supported enum reason;
* unresolved: its exact node alias appears in unresolved[] with a supported reason.
A parent selection never implicitly disposes of a nested candidate. A quoted
candidate can be rejected as an event with reason quote while its text remains a
separate quote part. Do not select the same candidate in conflicting arrays.
Contributions found outside this finite inventory may be selected from evidence.

Use candidate_inventory({start:0,limit:10}) and follow next_start until all
candidates are accounted. Use inspect_candidate({candidate_ref:"nX",start:0,
limit:12,max_characters:300}) for coherent paged subtree evidence. Follow its
next_start to see later body fields; bounded parent/header context repeats on
pages, so a chunk does not silently lose its author header. Context is a preview,
not an exact or complete field. Truncated text is not the full source.
An inventory node alias alone is not sufficient to choose author/body/time.
Inspect the actual subtree. Never guess that the next integer alias is a body.
Use the exact supported argument names. inspect_neighbors accepts max_nodes,
not depth or limit; inspect_node requires node_ref; inspect_candidate requires
candidate_ref. A host error includes the permitted arguments and bounded unknown
reference paths. Repair the identified source reference; never invent a value.
Unknown metadata does not prevent useful text extraction. Keep uncertainty honest.
